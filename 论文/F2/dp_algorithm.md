# F2 || ∑ W_j C_j 动态规划算法设计

基于最优解的分块结构性质，参考 F2|r_j|Cmax PTAS（Hall 1998 / Kovalyov & Werner 1997）中**区间划分 + 状态压缩**的动态规划思想，设计如下算法。

---

## 问题性质（来自 note.md）

1. **同排序性质**：两台机器上工件加工顺序一致（Permutation Schedule），已有经典结论。
2. **权重分块**：将工件按权重分为 K 类，W_1 > W_2 > ... > W_K。最优调度可划分为 K 个连续逻辑区间（块）。
3. **位置约束**：π(J_k) ≤ k，即第 k 类工件只能出现在前 k 个块中。
4. **块尾约束**：第 k 块的最后一个工件权重为 W_k。
5. **块内排序**：每个块内部的工件遵循 SPT(1)-LPT(2) 规则（Johnson 序）。

---

## 与 F2|r_j|Cmax PTAS 的对应关系

| F2\|r_j\|Cmax PTAS | 本算法 |
| --- | --- |
| 按释放日期 r_j 划分区间 | 按权重 W_k 划分区间（块） |
| 工件只能放入 r_j 对应的区间及之后 | 工件只能放入权重类对应的块及之前（π(J_k) ≤ k） |
| 区间内按 Johnson 序排列 | 块内按 Johnson 序排列 |
| DP 状态记录各区间的 M2 完工时间 | DP 状态记录当前调度序列的 A 与 B |
| 目标：最小化 Cmax | 目标：最小化 ∑ W_j C_j |

## 符号表

| 符号 | 含义 |
| --- | --- |
| n | 工件总数 |
| K | 权重类别数 |
| J_k | 权重为 W_k 的工件集合（k = 1,…,K） |
| W_k | J_k 的公共权重，W_1 > W_2 > … > W_K |
| n_k | \|J_k\|，第 k 类工件数 |
| a_j | 工件 j 在机器 1 上的加工时间 |
| b_j | 工件 j 在机器 2 上的加工时间 |
| w_j | 工件 j 的权重（j ∈ J_k ⇔ w_j = W_k） |
| L_k | J_k 按 Johnson 序排列后的有序列表 |
| π | 当前已构建的部分调度序列（工件的排列） |
| last_k | 当前 π 中 J_k 类工件出现的最靠后位置（无则为 0） |
| A | 按 π 的顺序在 M1 上加工完所有工件的累计时间 |
| B | 按 π 的顺序在 M2 上加工完所有工件的完工时间 |
| z | 按 π 的顺序加工所得累计加权完工时间和 ∑ w_j C_j |
| Y | DP 状态集合（当前部分调度及其评价值） |
| Z* | 最优（最小）总加权完工时间 |

## 算法描述

### 预处理

将工件按权重分组得到 J_1,…,J_K（W_1 > … > W_K）。对每组 J_k 内部按 Johnson 规则排序，得到有序列表 L_k = [j_{k,1}, …, j_{k,n_k}]。

### 核心思想

依次遍历 L_1 → L_2 → … → L_K 中的每个工件。对每个新工件 j ∈ J_k，在当前部分调度 π 的**每个可能位置**尝试插入，计算插入后的目标函数值，仅保留 z 最小的那个插入结果。同时，在每类工件全部处理完毕时**立即检查结构性质**，将不满足约束的状态提前剔除。

### 状态定义

$$(\pi,\; A,\; B,\; z,\; last_k)$$

- π：当前已安排工件的排列
- A, B, z：按 π 加工的累计评价值
- last_k：π 中当前 J_k 类工件的最后出现位置（若 J_k 尚未有任何工件，则 last_k = 0）

初始状态：(∅, 0, 0, 0, 0)。

### 单步决策——插入到每个位置

遍历到工件 j ∈ J_k，当前状态为 (π, A, B, z, last_k)。π 的长度 N = |π|。

**候选位置**：pos ∈ {0, 1, …, N}，共 N+1 个。每个 pos 表示将 j 插入到 π[pos] 之后（pos=0 表示插入到最前面）。

对每个候选位置 pos：

1. 构造 π' = π[1..pos] \|\| j \|\| π[pos+1..N]
2. 更新 last'_k = pos + 1（j 的新位置）
3. 对 π' 从头模拟流水车间加工，计算 (A', B', z')
4. **立即检查约束**（见下节）

### 插入时约束检查

在插入 j ∈ J_k 并更新 last'_k 后，检查以下条件：

1. **位置约束**（性质 3）：j ∈ J_k 可被插入到任意位置，位置约束由插入逻辑自动满足（j 不会被限制只能在哪些位置插入）。由于 J_{k+1}..J_K 尚未安排，j 不会落在块 k 之后。

2. **块尾约束**（性质 4）的递进检查：在插入 j 后，**仅当 j 是 J_k 类的最后一个工件（即 L_k 中全部工件已处理完）** 时，才检查：

   若当前是 L_k 的最后一个工件（i = n_k），则检查：
   $$last'_k \ge k$$

   该条件保证第 k 类最后一个工件的位置不早于 k，为前 k 个权重类各留出至少一个位置，从而满足块尾约束。若不满足，该状态非法，直接丢弃。

**为什么可以这样检查？** 当 J_k 类全部处理完毕后，last_k 记录了该类最后一个工件的位置。检查 last_k ≥ k 确保块结构有足够的空间容纳前 k 类工件。若该条件不满足（last_k < k），后续插入 J_{k+1}..J_K 的工件时，last_k 可能因插入点在其之前而右移，使得条件最终满足——因此此处做的是**必要性检查**而非充分性检查，用于提前剪枝以减少状态数。

### 保留最优

对每个状态 (π, A, B, z, last_k)，在尝试 j 的 N+1 个插入位置后，**仅保留 z' 最小的那些**作为新状态，丢弃其余。

### 提取最优

全部 n 个工件处理完毕后，所有存活的状态均满足四个结构性质。取 `min{ z | (π, A, B, z, last_k) ∈ Y }` 即得 Z*。

## 完整伪代码

```text
Algorithm DP_F2_WeightedSum(J, A, B, W):

    // ===== 预处理 =====
    Group jobs by weight → J_1..J_K (W_1 > ... > W_K)
    For k = 1 to K:
        L_k = Merge_By_Johnson(J_k)

    // ===== 初始化 =====
    Y = { (π=∅, A=0, B=0, z=0, last_k=0) }

    // ===== 依次遍历每个 L_k 的每个工件 =====
    for k = 1 to K:
        for i = 1 to n_k:
            j = L_k[i]              // 当前工件
            Y_new = ∅

            for each (π, A, B, z, last_k) ∈ Y:
                N = |π|
                best_z = +∞
                best_states = ∅

                // 尝试插入到每个候选位置
                for pos = 0 to N:
                    // 构造 π'
                    π' = π[1..pos] || j || π[pos+1..N]

                    // 更新 last'_k
                    last'_k = pos + 1

                    // 对 π' 模拟流水车间加工
                    A_cur = 0, B_cur = 0, z_cur = 0
                    for each job x in π' (按序):
                        A_cur = A_cur + a_x
                        B_cur = max(B_cur, A_cur) + b_x
                        z_cur = z_cur + w_x · B_cur

                    // 立即检查约束（递进）
                    valid = true
                    if i == n_k:                          // J_k 全部处理完毕
                        if last'_k < k:                   // 块尾检查
                            valid = false
                    if not valid:
                        continue                          // 丢弃此插入结果

                    // 保留最优
                    if z_cur < best_z:
                        best_z = z_cur
                        best_states = { (π', A_cur, B_cur, z_cur, last'_k) }
                    else if z_cur == best_z:
                        best_states = best_states ∪ { (π', A_cur, B_cur, z_cur, last'_k) }

                // 将最优插入结果加入新状态集合
                for each s ∈ best_states:
                    Insert s into Y_new

            Y ← Y_new

    // ===== 提取最优 =====
    return min{ z | (π, A, B, z, last_k) ∈ Y }
```

## 算法要点

1. **逐工件插入，逐位置尝试**：每个工件 j 到达时，尝试将其插入到部分调度 π 的每个位置（0 到 N），共 N+1 种可能。不区分"块"的边界——调度就是一个全局排列。

2. **约束在插入时立即检查**：位置约束由自然插入逻辑自动满足（j ∈ J_k 可被插入到任意位置）；块尾约束在 J_k 类全部处理完毕时检查 `last_k ≥ k`，一旦违反立即丢弃。

3. **全序模拟求精确值**：每次插入后对 π' 从头至尾模拟流水车间，精确计算 (A, B, z)。代价 O(|π|) 但避免了增量近似误差。

4. **每轮仅保留最优**：每个旧状态在加入一个工件后产生 N+1 个候选；算法仅保留 z 最小的那一个（或并列最优的少数几个）。

5. **无单独的终止校验**：因为约束已在每一轮递进检查完毕，全部工件处理完后无需再过滤——所有存活状态都是合法的。

---

## 复杂度分析

- **状态数**：在最坏情况下（所有插入位置 z' 均相等），|Y| 每轮可能翻 N+1 倍 ⇒ O(n!)。实践中"保留最优"策略使每轮状态增长极有限（通常在 O(1)~O(n) 量级）。

- **转移开销**：每轮每个状态尝试 O(N) 个位置，每次全序模拟 O(N) 步，合计每状态 O(N²) ≈ O(n²)。N 随遍历线性增长至 n。

- **总复杂度**：
  $$O\left(|Y|_{\max} \cdot n^3\right)$$

  其中 |Y|_max 为单轮最大状态数。此为一**迭代构造式**动态规划。每轮每个状态的转移开销因 last_k 简化为标量而降低：不再需要 O(K) 的数组复制与更新，仅需 O(1) 时间更新标量值。

- **PTAS 路径**：对权重做几何舍入使 K = O((1/ε) log W_max)，对加工时间做倍数舍入，即可在 poly(n, 1/ε) 时间内得到 (1+ε) 近似解。
